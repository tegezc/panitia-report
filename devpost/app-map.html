Panitia Report

A phone page for a neighborhood treasurer. She pastes two WhatsApp messages, checks the lines that do not read cleanly, and downloads a three-part PDF only when the written totals match and every yellow or red row is settled.

The pieces are index.html (the page), parse.js (the reading), app.js (the report and the gate), and pdf.js (the file). The report stays in this browser under panitia-report. Nothing is sent to a server.

One action

Download PDF stays grey, with a sentence under it, until the check is honest. This route is a reference. It was not walked in the editor.

Reference route

  1. index.html — search id="download" and id="download-note". The button is always labeled Download PDF. The note under it is the sentence she reads while the button is grey.
  2. app.js — search function gateOpen, function blockNote, and function incomeMatch. incomeMatch adds Opening balance to the donations before comparing them with Written total. rowNeedsCheck skips a Kas sisa row, so that hidden line does not keep the button grey. blockNote names a yellow or red row, or names which total is short.
  3. parse.js — search kas sisa and function reportFigures. A description matching Kas sisa sets saldoAwal on that income row. reportFigures subtracts it from donations. Closing balance is computed there and is never copied from a message.

To change this, start here

  • Button or note wording: index.html, id="download" and id="download-note". The same words are set again in app.js inside blockNote and drawReport.
  • What keeps Download PDF grey: app.js, function gateOpen.
  • How Kas sisa is recognized: parse.js, the kas sisa test. Leave that behavior in place unless a later plan says otherwise.
  • PDF columns: pdf.js, function buildPdfBytes, the three beginTable calls. Titles are separate from No., Nama, Jumlah, Uraian, and Keterangan.

A practice to reuse

The written Money in total looked Rp 500.000 short because Kas sisa was Opening balance and was not in the donations on screen. After incomeMatch counted it, that gap disappeared, and Download PDF stayed grey because Bpk H. Warga F was still a yellow amount. prd.md, section “The four numbers”, already said which sentence belongs to a yellow or red row and which sentence names a short total.

Name the sentence and the number you expect to see. A grey control is then either a row still open or a total that is short, and the sentence tells you which. The same check works on the next project: write the observable result in the requirements, then read that result before treating a stuck control as a new bug.
